## 1. 목표

**HRD 등록한 사람 중 개강날 실제로 오는 비율은 얼마이고, 취소하는 사람은 얼마이며, 누구인가**를 매일 자동으로 본다.
보는 곳은 노션 「HRD 등록자 관리」 페이지 하나 (2026-09-21부터. 그전 「모집 KPI」 페이지는 삭제).

| 질문 | 답이 있는 곳 |
|---|---|
| HRD 등록 대비 개강일 참석률 | 기수 표 `개강일 출석 인원(API)` · `개강 참석률(API, %)` |
| 등록 후 확정 신고 비율 | 기수 표 `확정 신고(API)` · `확정자 신고율(%)` (개강 + 7일부터) |
| 노션이 등록자를 빠짐없이 적었나 | 기수 표 `API 신청인원` vs `노션 수집 등록 인원` → `일치 여부` |
| 누구인가 | 기수 페이지 명단 표 (이름 · 등록일 · 개강날 출석 · 노션 상태 · HRD 승인) / 「등록자」 DB |
| 운영TF 구간 7 측정값 | `python scripts/tf_section7.py` (등록 = 노션 HRD등록·합격자등록 기준 참석률·기록 채움률·확정자 신고율) |

### 1-1. 기수 표 지표 — 원천과 계산식

"HRD 등록" = HRD-Net 수강신청. 분모는 셋 다 **API 신청인원** = HRD-Net 훈련일정 상세 API `totTrpCnt`(한 번이라도 신청한 사람의 누적, 취소자 포함). 운영TF 구간 7 정의와 같다.

| 지표 | 원천 데이터 | 계산식 | 값이 생기는 시점 |
|---|---|---|---|
| 노션 수집 등록 인원 | 신청자 리스트(AI캠퍼스·SKN)에서 HRD신청·HRD등록을 거쳤거나 HRD 신청/등록 일자가 있는 사람 | 인원수. API 신청인원과 같으면 일치 | 항상 |
| 개강 참석률 | HRD-Net 월별 출결 API. 개강일에 입실 시각이 있거나 출석 계열 상태면 '출석' | 개강일 출석 ÷ API 신청인원 × 100 | 개강 다음 날 |
| 확정자 신고율 | HRD-Net 훈련일정 상세 API `totParMks` = 확정 신고 인원 (명부 건수와 항상 같고, 노션 운영현황표 확정자신고와 일치) | 확정 신고 ÷ API 신청인원 × 100 | 개강 + 7일 (확정 신고가 개강 1주 뒤) |

읽는 법: 일치 여부가 '불일치'면 노션에 안 적힌 등록자가 있다는 뜻인데, 추적 시작(9/15) 전 취소자는 노션에 흔적이 없어 과거 기수는 대부분 불일치가 정상. 추적 후 기수(MLO3·AIO4·SKN38)는 일치. 확정자 신고율의 분모에는 개강 전에 승인되지 못한 신청자도 들어간다.

9/21 실측(7~9월 개강): 개강 참석률 65~80%, 확정자 신고율 50.0%(MLE2)~95.7%(SKN37), 9기수 합계 164/211 = 77.7%.

## 2. 상태 흐름과 기록 규칙

```
합격안내 → 합격자등록 → [HRD신청 (+ HRD 신청 일시)] → HRD등록 → (개강: 출결은 HRD-Net이 자동) 
                                   └──────── 언제든 ────────→ 합격취소(연락두절 | 신청자 요청) + 취소 상세 사유
```

| 순서 | 실제 업무 사건 | 노션에 적을 것 | 필수? | 파이프라인이 하는 일 |
|---|---|---|---|---|
| 1 | 합격 안내, 합격자 등록 | `최종결과` = 합격안내 → 합격자등록 (기존대로) | 기존 | 사람별 표에 `대기`로 등장 |
| 2 | 신청자가 HRD-Net에서 수강신청함 (본인이 알려주거나, HRD-Net 기관 화면 '수강신청' 목록에서 확인) | `최종결과` = **HRD신청** + `HRD 신청 일시` | **권장** | 여전히 `대기`. 사람별 표에서 '신청은 했고 승인 전'임이 보이고 신청→승인 소요일을 잴 수 있음 |
| 3 | **담당자가 HRD-Net 기관 화면에서 승인 처리** | `최종결과` = **HRD등록** — 승인 누른 직후 | **필수** | HRD 명부에 이름이 뜨면 `일치`. 이것이 KPI의 기준점 |
| 4 | 취소 (어느 단계든) | `최종결과` = 합격취소(…) + `취소 상세 사유`. **이미 승인했다면 HRD-Net에서도 취소 처리** | **필수** | 명부에서 빠지면 `취소`. HRD-Net 취소를 빼먹으면 `취소인데 명부 잔류`로 표시 |
| 5 | 개강 | 적을 것 없음 | — | HRD 출결에서 첫 입실을 읽어 `첫 참석일`·`개강일 참석` 계산 |

### 건너뛰어도 되는 것

- **2단계(HRD신청)는 건너뛰어도 된다.** 합격자등록 → 바로 HRD등록도 정상. 실제로 HRD등록 122명 중 `HRD 신청 일시`가 있는 사람은 32명(26%)뿐이고, 상태 전이 로그에도 합격안내 → HRD등록 직행이 보인다. 파이프라인은 HRD등록 하나만 있으면 돈다.
- 건너뛰면 잃는 것: 신청→승인에 며칠 걸리는지 못 잰다. (전에 있던 `놓침` 열은 2026-09-17 삭제 — HRD-Net 수강신청 수가 취소·미승인까지 누적이라 노션 누락과 구분이 안 됐다)

### 지켜야 하는 것 한 가지

**`HRD등록`은 "HRD-Net에서 승인이 끝났다"는 뜻으로만 쓴다.** 신청자가 "신청했어요"라고 한 시점에 HRD등록으로 올리면 승인될 때까지 사람별 표에 `노션만 등록`이 떠서 진짜 문제(이름 표기 불일치·승인 누락)와 구분이 안 된다. 그 시점엔 HRD신청을 쓰거나, 아무것도 바꾸지 않는다.

### 언제까지 적나

파이프라인은 하루 2회(약 13:30·18:35) 돈다. 승인 후 다음 실행 전에 적으면 흔적 없이 `일치`. 늦게 적으면 그 사이 `HRD만 승인`으로 잠깐 떴다가 사라진다 — 하루 안에만 맞추면 된다.

## 3. 판정 기준 (담당자가 어떻게 적든 파이프라인이 무엇을 기준으로 보나)

기준은 **노션 `HRD등록` ↔ HRD-Net 명부**. 기수 페이지 명단 표에서 이렇게 읽는다.

| 노션 상태 | HRD 승인(명부) | 뜻 · 조치 |
|---|---|---|
| HRD등록 | ✓ | 정상 |
| HRD등록 | 빈칸 | 승인 안 됐거나 이름 표기가 다름(띄어쓰기·개명). HRD-Net 화면 확인 |
| HRD신청 · 합격자등록 등 | ✓ | 승인은 됐는데 노션이 안 올라감 → HRD등록으로 갱신 |
| 합격취소(…) | ✓ | HRD-Net에서 취소 처리 안 됨 → 처리 |
| 노션에 없음 | ✓ | 명부에는 있는데 신청자 리스트에서 못 찾음 → 노션에 추가 또는 이름 확인 |
| (등록 이력 있음) | 빈칸 + 개강날 출석 '취소' | 등록했다가 명부에서 빠짐. 노션도 합격취소로 갱신 |

`HRD신청`·`HRD 신청 일시`는 있으면 등록일이 정확해지는 보조 정보.
